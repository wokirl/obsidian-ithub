## 1. Структура проекта

Минимальный консольный проект C# может выглядеть следующим образом:

```
MyFirstProject/
├── MyFirstProject.csproj
└── Program.cs
```

Проект может содержать множество файлов `.cs`. Их количество и названия не определяют, где находится точка входа.

### 1.1. Файл `.csproj`

`.csproj` (C# Project) — XML-файл с настройками проекта.

Он описывает параметры, которые необходимы инструментам .NET для обработки и сборки проекта.

Пример:

```
<Project Sdk="Microsoft.NET.Sdk">

  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <TargetFramework>net10.0</TargetFramework>
  </PropertyGroup>

</Project>
```

Основные элементы:

|Элемент|Назначение|
|---|---|
|`Project`|Корневой элемент проекта|
|`Sdk`|Указывает используемый SDK|
|`PropertyGroup`|Группа настроек|
|`OutputType`|Определяет тип результата сборки|
|`Exe`|Исполняемое приложение|
|`TargetFramework`|Целевая платформа .NET|

**Важно:** `.csproj` содержит настройки проекта, а не основную программную логику.

### 1.2. Файлы `.cs`

Файлы с расширением `.cs` содержат исходный код на языке C#.

Например:

```
Console.WriteLine("Hello World");
```

`Program.cs` — распространённое название файла, в котором размещается начальный код приложения.

Однако компилятор не требует, чтобы файл с точкой входа обязательно назывался `Program.cs`.

Точку входа можно разместить в файле с любым допустимым названием.

## 2. Точка входа программы

**Точка входа (Entry Point)** — место, с которого начинается выполнение приложения.

В традиционной форме C# точкой входа является метод `Main`.

Пример:

```
class Program
{
    static void Main()
    {
        Console.WriteLine("Hello World");
    }
}
```

### 2.1. Разбор конструкции

|Элемент|Значение|
|---|---|
|`class`|Объявляет класс|
|`Program`|Имя класса|
|`static`|Метод принадлежит типу, а не экземпляру объекта|
|`void`|Метод не возвращает результат|
|`Main`|Имя метода, который может быть точкой входа|
|`{ }`|Ограничивают тело класса или метода|

**Главное:** метод `Main` является специальным методом с точки зрения правил запуска приложения. Но не любой метод с таким именем автоматически становится точкой входа.

Метод должен соответствовать требованиям C# к точке входа.

## 3. Top-level statements

Современный C# поддерживает механизм **Top-level statements** — инструкции верхнего уровня.

Он позволяет писать код без явного объявления класса и метода `Main`.

Пример:

```
Console.WriteLine("Hello World");
Console.WriteLine("Second line");
```

Компилятор самостоятельно формирует необходимую структуру программы, включая точку входа.

Таким образом, отсутствие `Main` в исходном коде не означает, что у программы отсутствует точка входа.

### Сравнение двух подходов

**Традиционный подход:**

```
class Program
{
    static void Main()
    {
        Console.WriteLine("Hello World");
    }
}
```

**Top-level statements:**

```
Console.WriteLine("Hello World");
```

|Традиционный подход|Top-level statements|
|---|---|
|`Main` объявляется вручную|Точка входа формируется компилятором|
|Необходимо объявить класс|Не нужно вручную объявлять класс|
|Явная структура|Более короткая запись|

## 4. Несколько методов Main

В проекте технически могут существовать несколько методов `Main`.

Например:

```
class Player
{
    static void Main()
    {
        Console.WriteLine("Player");
    }
}

class Engine
{
    static void Main()
    {
        Console.WriteLine("Engine");
    }
}
```

Оба метода могут соответствовать требованиям точки входа.

Однако компилятор должен определить, какой именно использовать.

Если подходящих кандидатов несколько и выбор не задан, возникает ошибка неоднозначности точки входа.

**Важное различие:**

- Метод `Main` — метод, который может выступать точкой входа.
    
- Точка входа — конкретный метод, выбранный для запуска приложения.
    

Несколько методов `Main` не означают, что программа будет запускать их все последовательно.

## 5. Выбор точки входа через StartupObject

Для явного выбора точки входа можно использовать настройку `StartupObject` в `.csproj`.

Например:

```
<Project Sdk="Microsoft.NET.Sdk">

  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <TargetFramework>net10.0</TargetFramework>
    <StartupObject>Player</StartupObject>
  </PropertyGroup>

</Project>
```

Теперь компилятор будет использовать метод `Main` класса `Player`.

Метод `Main` класса `Engine` останется в программе, но не будет автоматически вызываться при запуске.

### Что делает StartupObject?

1. Указывает класс, содержащий нужную точку входа.
    
2. Позволяет разрешить неоднозначность между несколькими подходящими методами `Main`.
    
3. Не удаляет остальные методы `Main`.
    
4. Не запрещает вызывать другие методы обычным способом.
    

**Важно:** `StartupObject` указывает именно класс, а не имя метода.

Указанный класс должен содержать подходящий метод `Main`.

## 6. Принципиальные различия

|Понятие|Назначение|
|---|---|
|`.csproj`|Настройки проекта|
|`.cs`|Исходный код C#|
|`Program.cs`|Распространённое название файла с начальным кодом|
|`Main`|Метод, который может быть точкой входа|
|Top-level statements|Синтаксис, позволяющий не объявлять `Main` вручную|
|Entry Point|Конкретная точка начала выполнения|
|`StartupObject`|Настройка выбора класса с точкой входа|

## 8. Принципы, которые важно усвоить

1. **Файл и точка входа — разные понятия.** `Program.cs` не является точкой входа сам по себе.
    
2. **Название файла не определяет запуск.** Точка входа может находиться в любом подходящем `.cs`-файле.
    
3. `**.csproj**` **отвечает за настройки проекта.** В нём не размещается обычная программная логика.
    
4. **Отсутствие явного** `**Main**` **не означает отсутствие точки входа.** Её может сформировать компилятор при использовании Top-level statements.
    
5. **Метод и точка входа — не одно и то же.** В проекте может быть несколько методов `Main`, но должна быть однозначно выбрана точка входа.
