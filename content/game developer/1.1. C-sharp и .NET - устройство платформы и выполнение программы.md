## 1. C# и .NET

C# и .NET - два разных, но тесно связанных понятия.

### C# (C Sharp)

**C# - язык программирования.**

Он определяет правила написания программ:

- синтаксис;
    
- переменные и типы данных;
    
- методы;
    
- классы и структуры;
    
- условия и циклы;
    
- правила взаимодействия между элементами программы.
    

C# определяет, как мы описываем логику программы.

### .NET

**.NET - платформа разработки и выполнения программ.**

Она предоставляет:

- стандартные библиотеки;
    
- среду выполнения;
    
- управление памятью;
    
- средства работы с файлами;
    
- инструменты сетевого взаимодействия;
    
- механизмы взаимодействия с операционной системой.
    

Например:

```
Console.WriteLine("Hello World");
```

Разбор:

- `Console` - класс из библиотеки .NET;
    
- `WriteLine` - метод этого класса;
    
- `"Hello World"` - передаваемая строка.
    

Синтаксис вызова метода определяется языком C#, а реализация `Console.WriteLine()` предоставляется библиотекой .NET.

**Главное различие:**

C# позволяет описать программу, а .NET предоставляет готовые механизмы, которые помогают этой программе работать.

---

## 2. Можно ли использовать C# без .NET?

Теоретически да.

C# не требует обязательного использования именно стандартной платформы .NET, но для выполнения программы всё равно необходима подходящая среда и реализация используемых механизмов.

Например, рассмотрим:

```
Console.WriteLine("Hello World");
```

Метод `Console.WriteLine()` предоставляется библиотекой .NET.

Если убрать эту библиотеку, конкретный вызов больше не будет доступен, если мы не предоставим собственную реализацию.

Например, можно самостоятельно реализовать вывод текста через Windows API.

Таким образом, язык C# не требует обязательного использования именно `Console.WriteLine()`.

### Важный принцип

Язык программирования и библиотека - не одно и то же.

Мы можем использовать разные реализации одной функциональности, если обеспечим необходимое поведение.

## 3. Компилятор C#

Компилятор C# преобразует исходный код программы в промежуточное представление IL.

Компилятор выполняет в том числе проверку исходного кода и обнаруживает ошибки, которые можно выявить на этапе компиляции.

Упрощённый пример:

```
Console.WriteLine("Hello World");
```

Исходный код проходит компиляцию, в результате которой формируется промежуточный код.

---

## 4. IL (Intermediate Language)

**IL - промежуточный язык, в который компилируется исходный код C#.**

IL не является обычным исходным кодом C# и не является машинным кодом конкретного процессора.

Он предназначен для дальнейшего выполнения в совместимой среде .NET.

Другие языки, например F# и Visual Basic .NET, также могут компилироваться в IL.

Это позволяет разным языкам использовать общую инфраструктуру .NET и взаимодействовать между собой.

---

## 5. CLR (Common Language Runtime)

**CLR - среда выполнения управляемого кода .NET.**

Она организует выполнение программы и предоставляет необходимые механизмы во время её работы.

Основные обязанности CLR:

- организация выполнения управляемого кода;
    
- взаимодействие с JIT;
    
- управление памятью через Garbage Collector;
    
- обработка исключений;
    
- предоставление механизмов выполнения и контроля кода.
    

CLR не является языком программирования и не является компилятором C#.

Это компонент платформы .NET, отвечающий за организацию выполнения программы.

---

## 6. JIT (Just-In-Time Compiler)

**JIT - компилятор, который преобразует IL в машинный код во время выполнения программы.**

Процессор не может непосредственно выполнять IL. Ему необходимы машинные инструкции, соответствующие его архитектуре.

Поэтому JIT преобразует промежуточный код в машинный код, который может выполнять процессор.

JIT является одним из механизмов среды выполнения .NET.

## 7. Полная последовательность выполнения программы

Упрощённая схема:

## 8. Несколько языков - одна среда выполнения

.NET не ограничивается языком C#.

Например:

```
flowchart TD
    A["C#"] --> D["IL"]
    B["F#"] --> D
    C["Visual Basic .NET"] --> D
    D --> E["CLR"]
    E --> F["Машинный код"]
```

CLR не обязана знать, на каком языке изначально была написана программа.

Главное, чтобы результат компиляции соответствовал требованиям среды выполнения и был совместим с её механизмами.

При этом у разных языков могут быть собственные особенности, которые компилятор должен корректно представить в IL.

## 9. Важные принципы

> [!IMPORTANT] Язык и платформа  
> C# и .NET - разные понятия. Язык описывает программу, платформа предоставляет инфраструктуру для её выполнения.

> [!IMPORTANT] Библиотеки и собственные реализации  
> Использование конкретной библиотеки не всегда обязательно. При необходимости её функциональность можно реализовать самостоятельно.

> [!IMPORTANT] Промежуточный код  
> IL не является машинным кодом. Он предназначен для дальнейшего выполнения совместимой средой.

> [!IMPORTANT] CLR и JIT  
> CLR организует выполнение программы, а JIT преобразует IL в машинный код. JIT - один из механизмов CLR, а не вся среда выполнения.

## 11. Принципы, вызвавшие больше всего вопросов

### 1. Различие языка и платформы

Основная трудность заключалась в понимании того, почему C# и .NET не являются одним и тем же.

Ключевой вывод: язык определяет правила написания программы, а платформа предоставляет готовые механизмы.

### 2. Замена библиотечной функциональности

Возник вопрос, можно ли использовать C# без стандартного метода `Console.WriteLine()`.

В ходе обсуждения был усвоен принцип: конкретная библиотечная реализация может быть заменена собственной.

### 3. Назначение CLR

Потребовалось дополнительное объяснение того, что означает среда выполнения.

Ключевой вывод: CLR организует выполнение управляемого кода и предоставляет необходимые механизмы во время работы программы.

### 4. Отношение CLR и JIT

Усвоено, что JIT не является всей CLR. Он отвечает за преобразование IL в машинный код и является частью механизмов среды выполнения.
