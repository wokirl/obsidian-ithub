## 1. Что такое канальный уровень?

**Канальный уровень (Data Link Layer, L2)** - второй уровень модели [[OSI]]. Он отвечает за передачу данных между устройствами в пределах одного канала связи или локального сетевого сегмента.

Основные задачи канального уровня:

- Формирование кадров из передаваемых данных.
    
- Адресация устройств с помощью MAC-адресов.
    
- Передача кадров между непосредственно связанными узлами.
    
- Обнаружение ошибок передачи.
    
- Управление доступом к общей среде передачи, если это предусмотрено технологией.
    

Например, когда компьютер отправляет данные другому компьютеру в той же локальной сети Ethernet, канальный уровень формирует кадр и указывает в нем MAC-адреса отправителя и получателя.

> [!important] Главная задача L2  
> Обеспечить передачу кадров между устройствами в пределах соответствующего канального сегмента, используя правила конкретной технологии - например, Ethernet или Wi-Fi.

## 2. Что такое кадр (Frame)?

**Кадр (Frame)** - структурированная единица данных канального уровня. Он содержит полезные данные и служебные поля, необходимые для передачи по каналу связи.

Когда данные проходят через уровни модели OSI, на каждом уровне они могут получать дополнительную служебную информацию.

Упрощенная последовательность:

```
Данные приложения
       ↓
Сегмент TCP / датаграмма UDP
       ↓
IP-пакет (L3)
       ↓
Кадр Ethernet (L2)
       ↓
Биты и физические сигналы (L1)
```

Названия единиц данных зависят от уровня и используемого протокола.

### 2.1. Из чего состоит Ethernet-кадр?

В упрощенном виде Ethernet-кадр включает три основные части:

```
┌─────────────────────┬──────────────────────┬─────────────────┐
│ Заголовок (Header)  │ Данные (Payload)      │ FCS             │
│                     │                      │ Контрольная     │
│ MAC-адреса, тип     │ Полезная информация  │ последователь-  │
│ протокола и другие  │                      │ ность           │
│ поля                │                      │                 │
└─────────────────────┴──────────────────────┴─────────────────┘
```

**Заголовок (Header)** содержит служебные сведения, в частности:

- MAC-адрес назначения.
    
- MAC-адрес источника.
    
- Поле типа протокола или длины данных.
    

**Полезные данные (Payload)** - информация, которую передают вышележащие уровни. Например, внутри Ethernet-кадра может находиться IP-пакет.

**FCS (Frame Check Sequence)** - поле контроля целостности кадра. В обычном Ethernet оно содержит значение CRC, вычисленное для обнаружения ошибок передачи.

> [!note] CRC не исправляет ошибки  
> CRC помогает обнаружить повреждение данных, но сам по себе не восстанавливает испорченные биты. Повторная передача или исправление ошибок обеспечиваются другими механизмами, если они предусмотрены используемой технологией.

### 2.2. Ethernet и Wi-Fi

Ethernet и Wi-Fi используют разные форматы кадров.

- **Ethernet** применяется преимущественно в проводных локальных сетях.
    
- **Wi-Fi** использует кадры стандарта IEEE 802.11 и предусматривает дополнительные поля, связанные с управлением беспроводным соединением и передачей данных.
    

Общий принцип остается похожим: кадр содержит адресную и служебную информацию, а также передаваемые данные.

## 3. Что такое MAC-адрес?

**MAC-адрес (Media Access Control address)** - адрес канального уровня, используемый для идентификации сетевого интерфейса в соответствующей технологии и сетевом сегменте.

Типичный MAC-адрес Ethernet имеет длину 48 бит, то есть 6 байтов.

Пример:

```
A4:5E:60:12:AB:CD
```

Каждая пара шестнадцатеричных символов соответствует одному байту.

### 3.1. Для чего нужен MAC-адрес?

Коммутаторы Ethernet используют MAC-адреса, чтобы определять, на какой порт нужно передать кадр.

Представим локальную сеть из трех устройств:

```
Компьютер A
MAC: AA:AA:AA:AA:AA:AA
          │
          ▼
     Коммутатор
       /     \
      ▼       ▼
Компьютер B  Компьютер C
MAC: BB:...  MAC: CC:...
```

Если компьютер A отправляет кадр компьютеру B, в поле назначения указывается MAC-адрес компьютера B.

Коммутатор анализирует этот адрес и, если знает соответствующий порт, пересылает кадр в нужном направлении.

### 3.2. MAC-адрес и IP-адрес - в чем разница?

|Характеристика|MAC-адрес|IP-адрес|
|---|---|---|
|Уровень модели OSI|Канальный (L2)|Сетевой (L3)|
|Основное назначение|Передача кадров в канальном сегменте|Адресация и доставка пакетов между сетями|
|Пример|`A4:5E:60:12:AB:CD`|`192.168.1.10`|
|Использование маршрутизаторами|Не определяет конечный путь через все сети|Используется при маршрутизации|

> [!important] Главное различие  
> IP-адрес помогает определить, куда нужно доставить пакет на сетевом уровне. MAC-адрес используется для доставки кадра в конкретном канальном сегменте.

Например, при отправке данных на удаленный сервер компьютер обычно формирует Ethernet-кадр, адресованный MAC-адресу локального маршрутизатора. При этом IP-пакет внутри кадра адресован удаленному серверу.

На следующем участке пути кадр может быть сформирован заново с другими MAC-адресами.

MAC-адреса не следует считать абсолютно неизменными или гарантированно уникальными во всех сетях: их можно программно изменить, а из-за ошибок настройки или производства возможны дубликаты.

## 4. Как работает коммутатор?

**Коммутатор (Switch)** - сетевое устройство, которое в обычном случае работает на канальном уровне и пересылает Ethernet-кадры между портами на основе MAC-адресов.

Для этого он использует таблицу коммутации, также называемую MAC-таблицей.

### 4.1. Что хранится в MAC-таблице?

Коммутатор запоминает, с какого порта пришел кадр и какой MAC-адрес был указан в качестве адреса источника.

Пример таблицы:

|MAC-адрес|Порт|
|---|---|
|`AA:AA:AA:AA:AA:AA`|1|
|`BB:BB:BB:BB:BB:BB`|2|
|`CC:CC:CC:CC:CC:CC`|3|

Если коммутатор получает кадр для MAC-адреса `BB:BB:BB:BB:BB:BB`, он проверяет таблицу и пересылает кадр через порт 2, если адрес известен и находится в соответствующем VLAN.

Таблица обычно обучается автоматически в процессе работы сети. Записи могут удаляться после истечения времени хранения.

### 4.2. Как коммутатор обрабатывает кадр?

Упрощенный алгоритм:

1. Коммутатор получает кадр на одном из портов.
    
2. Изучает MAC-адрес источника и обновляет таблицу коммутации.
    
3. Проверяет MAC-адрес назначения.
    
4. Если адрес назначения известен, пересылает кадр через соответствующий порт.
    
5. Если адрес назначения неизвестен, обычно отправляет кадр на остальные подходящие порты в пределах того же VLAN, кроме входного порта.
    
6. Широковещательные кадры также распространяются в пределах соответствующего широковещательного домена.
    

Исключения зависят от настроек, фильтрации, VLAN и особенностей оборудования.

> [!tip] Как запомнить  
> Коммутатор обучается по **MAC-адресу источника**, а решение о пересылке принимает по **MAC-адресу назначения**.

### 4.3. Чем коммутатор отличается от концентратора?

**Концентратор (Hub)** работает на физическом уровне. Он повторяет поступивший сигнал на остальные порты, не анализируя MAC-адреса.

**Коммутатор (Switch)** анализирует кадры и может передавать их только в нужный порт, если адрес назначения известен.

|Характеристика|Hub|Switch|
|---|---|---|
|Уровень OSI|L1|Обычно L2|
|Анализ MAC-адресов|Нет|Да|
|Пересылка трафика|Повторяет сигнал на другие порты|Выбирает порт по MAC-таблице|
|Коллизии в классической общей среде|Возможны|В полнодуплексных соединениях Ethernet отсутствуют|

Современные локальные сети Ethernet обычно строятся на коммутаторах.

## 5. Подуровни канального уровня: MAC и LLC

Канальный уровень в классической модели IEEE 802 разделяется на два подуровня.

### 5.1. MAC (Media Access Control)

Подуровень MAC отвечает за правила доступа к среде передачи и работу с адресами канального уровня.

Его задачи зависят от технологии и могут включать:

- Использование MAC-адресов.
    
- Формирование и обработку кадров.
    
- Управление доступом к среде передачи.
    
- Проверку целостности кадров.
    

Например, в классическом Ethernet с общей средой использовался механизм CSMA/CD, позволявший обнаруживать коллизии.

В современных коммутируемых полнодуплексных сетях Ethernet CSMA/CD обычно не используется, поскольку каждый порт образует отдельный канал связи без коллизий в классическом смысле.

### 5.2. LLC (Logical Link Control)

Подуровень LLC обеспечивает логический интерфейс между канальным и сетевым уровнями.

Он помогает различать протоколы верхнего уровня и предоставляет соответствующие механизмы взаимодействия.

> [!note] Не все функции L2 реализованы одинаково  
> Реальное устройство канального уровня зависит от технологии. Например, Ethernet и Wi-Fi используют разные механизмы доступа к среде и разные форматы кадров.

## 6. Основные технологии и протоколы канального уровня

Канальный уровень представлен большим количеством технологий, предназначенных для разных условий связи.

### Ethernet

Наиболее распространенная технология проводных локальных сетей. Использует кадры Ethernet и MAC-адреса.

### Wi-Fi (IEEE 802.11)

Семейство стандартов беспроводных локальных сетей. Использует кадры 802.11 и собственные механизмы доступа к радиосреде.

### VLAN (Virtual Local Area Network)

**VLAN** позволяет логически разделять одну физическую коммутируемую инфраструктуру на несколько виртуальных локальных сетей.

Например, в одном офисе можно разделить устройства на группы:

- VLAN 10 - сотрудники.
    
- VLAN 20 - гости.
    
- VLAN 30 - серверы.
    

Даже если устройства подключены к одним и тем же физическим коммутаторам, они могут находиться в разных широковещательных доменах.

Для обмена IP-трафиком между VLAN обычно требуется маршрутизация на устройстве третьего уровня или на маршрутизаторе.

> [!important] VLAN - это логическое разделение  
> VLAN не обязательно требует отдельных физических коммутаторов или отдельных кабельных систем для каждой группы. Разделение обеспечивается конфигурацией сетевого оборудования.

### Другие технологии

|Технология|Назначение|
|---|---|
|PPP (Point-to-Point Protocol)|Передача данных по прямому соединению между двумя узлами|
|HDLC|Протокол канального уровня для последовательных линий связи|
|Fibre Channel|Высокоскоростное соединение в сетях хранения данных (SAN)|
|Frame Relay|Историческая технология передачи данных через виртуальные каналы|
|Token Ring|Историческая технология локальных сетей с передачей маркера|

Некоторые из этих технологий сегодня встречаются преимущественно в специализированных или унаследованных инфраструктурах.

## 7. Что произойдет, если два устройства имеют одинаковый MAC-адрес?

В пределах одного канального сегмента и одного VLAN одинаковые MAC-адреса могут вызвать проблемы с доставкой кадров.

В нормальной ситуации коммутатор ожидает, что конкретный MAC-адрес будет связан с определенным портом в пределах соответствующего VLAN.

Предположим, два устройства используют один и тот же MAC-адрес:

```
Устройство A                    Устройство B
MAC: AA:AA:AA:AA:AA:AA         MAC: AA:AA:AA:AA:AA:AA
       │                              │
     Порт 1                         Порт 2
       │                              │
       └────────── Коммутатор ────────┘
```

Когда кадр от устройства A приходит через порт 1, коммутатор может связать MAC-адрес с портом 1.

Затем кадр от устройства B приходит через порт 2. Коммутатор видит тот же MAC-адрес источника и может обновить запись, связав адрес уже с портом 2.

Если это повторяется, запись начинает переключаться между портами.

Такое поведение называется **MAC flapping** - перемещение одного MAC-адреса между портами коммутатора.

### 7.1. Возможные последствия

**Потеря кадров**

Коммутатор может пересылать кадры на порт, за которым временно числится MAC-адрес, хотя ожидаемое устройство подключено к другому порту.

**Нестабильная связь**

Доставка кадров становится непредсказуемой. Одно или оба устройства могут испытывать проблемы с соединением.

**Проблемы с сетевыми протоколами**

Если кадры поступают не тому устройству, обмен данными на более высоких уровнях также может нарушаться.

**Диагностические сообщения**

Управляемые коммутаторы могут регистрировать перемещение MAC-адресов между портами. Такие сообщения помогают обнаруживать ошибки подключения, петли и другие аномалии.

> [!warning] Не путай MAC-конфликт с коллизией Ethernet  
> Одинаковые MAC-адреса не означают, что электрические сигналы обязательно столкнутся друг с другом. Основная проблема заключается в неоднозначной адресации и неправильной пересылке кадров.

### 7.2. Может ли возникнуть широковещательный шторм?

Сам по себе дублирующийся MAC-адрес не обязательно приводит к широковещательному шторму.

Шторм широковещания - это чрезмерное распространение широковещательных кадров по сети. Он может возникать, например, из-за петель второго уровня или определенных неисправностей.

Дублирование MAC-адресов и широковещательные штормы - разные проблемы, хотя они могут встречаться одновременно.

### 7.3. Что будет, если одинаковые MAC-адреса находятся в разных VLAN?

Одинаковые MAC-адреса в разных VLAN обычно не создают такого конфликта, поскольку коммутатор рассматривает таблицу MAC-адресов с учетом VLAN.

Фактически записи относятся к разным логическим канальным сегментам.

Однако это не означает, что дублирование адресов безопасно во всех обстоятельствах: многое зависит от топологии, маршрутизации, настроек оборудования и характера дубликатов.

### 7.4. Как искать проблему?

Если подозреваешь конфликт MAC-адресов:

1. Проверь MAC-адреса устройств.
    
2. Посмотри MAC-таблицу коммутатора.
    
3. Проверь, не перемещается ли один адрес между портами.
    
4. Убедись, что устройства подключены к правильным VLAN.
    
5. Проверь кабели, подключения и наличие сетевых петель.
    
6. Изучи журналы событий управляемого коммутатора.
    

Не стоит сразу менять MAC-адреса: сначала нужно установить причину дублирования.

## 8. Практический пример: компьютер отправляет данные через коммутатор

Предположим, компьютер A должен передать данные компьютеру B в одной локальной сети.

```
Компьютер A             Коммутатор             Компьютер B
     │                       │                       │
     │──── Ethernet-кадр ───>│                       │
     │                       │                       │
     │                       │──── Ethernet-кадр ───>│
     │                       │                       │
```

Процесс выглядит следующим образом:

1. Компьютер A определяет MAC-адрес получателя. Если он знает IP-адрес B, но не знает его MAC-адрес, в IPv4-сети может потребоваться ARP-запрос.
    
2. Компьютер A формирует Ethernet-кадр с MAC-адресом назначения B.
    
3. Коммутатор получает кадр и изучает MAC-адрес источника A.
    
4. Коммутатор проверяет таблицу и находит порт, связанный с MAC-адресом B.
    
5. Кадр пересылается через нужный порт.
    
6. Компьютер B получает кадр и передает содержащиеся в нем данные вышележащему уровню.
    

Если MAC-адрес назначения неизвестен коммутатору, кадр обычно рассылается на подходящие порты внутри VLAN, кроме входного. Это называется **флудингом неизвестного одноадресного кадра** (unknown unicast flooding).

## 9. Как связаны L1, L2 и L3?

Для понимания сетей важно видеть не только функции отдельных уровней, но и их взаимосвязь.

|Уровень|Основная задача|Пример|
|---|---|---|
|L1 - физический|Передача сигналов и битов|Кабель, оптика, радиоканал|
|L2 - канальный|Передача кадров внутри канального сегмента|Ethernet, MAC-адреса, коммутатор|
|L3 - сетевой|Адресация и маршрутизация между сетями|IP, маршрутизатор|

Например, при отправке данных на сервер в интернете:

1. На уровне L3 определяется IP-адрес назначения.
    
2. Если сервер находится в другой сети, компьютер отправляет пакет через локальный маршрутизатор.
    
3. На уровне L2 формируется кадр, адресованный MAC-адресу маршрутизатора.
    
4. На уровне L1 биты передаются в виде физических сигналов.
    
5. Маршрутизатор принимает кадр, обрабатывает IP-пакет и формирует новый кадр для следующего участка пути.
    

Таким образом, MAC-адрес используется для доставки кадра на текущем участке канального пути, а IP-адрес помогает доставлять пакет к конечной сети назначения.

## 10. Краткое резюме

- **Канальный уровень (L2)** - второй уровень модели OSI.
    
- **Кадр (Frame)** - единица данных канального уровня.
    
- **MAC-адрес** используется для адресации сетевых интерфейсов в канальном сегменте.
    
- **Коммутатор** изучает MAC-адреса источников и использует MAC-таблицу для пересылки кадров.
    
- **Hub** повторяет сигналы на физическом уровне, а коммутатор пересылает кадры с учетом адресов.
    
- **MAC и LLC** - два подуровня, выделяемые в классической модели IEEE 802.
    
- **VLAN** позволяет логически разделять сеть на отдельные широковещательные домены.
    
- **Дублирование MAC-адресов** в одном VLAN может вызывать MAC flapping и потерю кадров.
    
- **CRC** помогает обнаруживать повреждения кадров, но не исправляет их самостоятельно.
    
- L2 обеспечивает передачу кадров, тогда как L3 отвечает за IP-адресацию и маршрутизацию.
    

> [!quote] Главная мысль  
> **Канальный уровень определяет, как данные передаются кадрами между устройствами в пределах локального канального сегмента. MAC-адреса и таблицы коммутации позволяют доставлять кадры нужным получателям.**
